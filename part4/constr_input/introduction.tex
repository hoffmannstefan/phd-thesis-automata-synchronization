Here, we investigate the constrained synchronization problem when the input is restricted to the following classes of  automata:
\begin{enumerate} 
\item monotonic automata (Section~\ref{constr_sync:subsec:monotonic_aut}),
\item partially ordered automata (Section~\ref{constr_input:subsec:pto}),
\item $\rho$-automata with a trap state (Section~\ref{constr_input:subsec:rho}),
\item commutative and unary automata (Section~\ref{constr_input:subsec:comm}), 
\item solvable $\rho$-automata (Section~\ref{constr_input:subsec:solvable}),
\item binary SI-automata (Section~\ref{constr_input:subsec:SI-automata}).
\end{enumerate}

 noted that $\constrsync{L}$ w.r.t.~any $\Sigma$ with $L \subseteq \Sigma^*$
 gives the same complexity for~$\leACZEROm$-reductions.
 When restricting the input to subclasses of automata,
 this only holds for subclasses closed for

 from Remark~\ref{constrsync:rem:alphabet},

 input automata to some subalphabet.

\begin{remark}
	An automaton $\mathcal a$ is a \rYES-instance for $\constrsync{L}$
	if and only if $\Syn(\mathcal A) \cap L \ne \emptyset$.
	Since we have $\Syn(\mathcal A) = \Syn\left(\mathcal A^{\le 2} / {\sim_F}\right)$ where $F = \{\{q\} \mid q \in Q\}$
	by \cref{prelim:subclasses:sync:Aiffpairaut},
	and the pair automaton $\mathcal A^{\le 2} / {\sim_F}$ has a trap state and can be computed 
	in polynomial time. Thus, up to polynomial time,
	$\constrsync{L}$ is equivalent to constrained synchronization problem with constraint language~$L$
	restricted to automata 
	with a trap state as input. Thus all our \NP- and \PSPACE-hardness
	results also hold for trap-state input automata up to polynomial-time many-one
	reductions.
\end{remark}

\begin{remark}
	When restricting the type of input automata care has to be taken
	when using some of the general results from \cref{constr_sync:chap:gen_results} 
	since some reductions alter the input automaton,
	which might result in automata that are not contained in 
	some class of automata under consideration.
	We note that general results solely based
	on \cref{constr_sync:cor:factors_sets_included,gen_results:cor:factors_etc_complexity}, i.e.,
	the equality of factor sets of constraint automata, work for every class
	of automata since they do not alter the input automaton at all.	
\end{remark}
